关于.Net

.Net是微软提供的技术平台的代号

框架体系 ：.Net Framework、 .Net core、 mono等
**开发语言：**C# VB F#等等

微软做.Net平台的目的：跨语言、跨平台

如何实现跨语言

CLS(common language specification)，公共语言规范
只要所有语言都遵守 CLS 规则，它们写出来的代码编译后都能变成中间语言（IL），所以可以互相调用

CLI (Common Language Infrastructure)，公共语言基础结构
整个 .NET运行体系标准，国际工业标准

CTS (Common Type System)，公共类型系统
所有 .NET 语言必须遵守的“数据类型统一规则”，CLS是CTS的子级
int 在所有语言中必须统一：
System.Int32
string 必须统一：
System.String
bool 必须统一：
System.Boolean

如何实现跨平台
.Net Framework框架 2002
主要用于开发window下的应用程序，部分开源

不同语言使用类库-->编译-->生成程序集(.dll(IL 元数据 资源) .exe)-->CLR(负责运行管理)-->JIT(在CLR里面，翻译机器码)-->window

CLR(common language runtime)，公共语言进行时
微软写好的代码，用来管理我们写的代码。提供内存、管理线程管理等等核心服务，像小操作系统。被称为‘.Net虚拟机’

CLR负责：
加载程序（DLL/EXE）
管理内存（GC）
类型系统
执行流程控制
决定什么时候需要编译

.Net Core框架 2016

1.把之前的类库拓展成支持多个操作系统的类库
2.NET Core（现在叫 .NET）提供跨平台运行时（CoreCLR），同一份IL在不同操作系统上运行时，通过不同运行时 + JIT生成对应机器码

Mono

与.Net Core的区别在于，库里面有些mono的公共库

.Net跨语言和跨平台原理
.NET 的跨语言依赖 CLI 体系，包括 CTS 和 CLS。CTS 统一了所有语言的数据类型，CLS 规定语言互通的公共规则，所以不同语言（C#、VB等）最终都会被编译成统一的中间语言 IL，因此可以实现跨语言互操作。

IL 不能直接被 CPU 执行，需要依赖 .NET 运行时（如 CLR / CoreCLR / Mono）加载程序集并执行。运行时在方法首次执行时通过 JIT 将 IL 即时编译为当前操作系统和 CPU 架构对应的机器码，然后交由 CPU 执行。因此，只要不同平台提供对应实现的 .NET 运行时，就可以运行同一份 IL 程序，就可以实现跨平台。

补充
JIT在方法第一次调用时执行

IL是不是跨平台？
IL本身是平台无关的中间语言，但它不能直接运行，跨平台能力来自不同平台的 .NET 运行时

CLR是.NET的运行时，JVM是Java的运行时，它们都负责把中间代码（IL / bytecode）通过JIT转成机器码执行。

名字： 是什么
.NET Runtime： 总称（整个运行环境）
CLR： .NET Framework 的运行时
CoreCLR： .NET Core / .NET 5+ 的运行时
Mono： 跨平台实现（Unity常用）

.NET设计IL的原因主要有三个：
一是为了支持多语言统一，比如C#和VB最后都变成IL；（为什么要IL）
二是因为CPU只能执行机器码，所以需要运行时调用JIT去做转换；（没有JIT行不行）
三优化和安全交给运行时。（CLR和操作系统是什么关系）
